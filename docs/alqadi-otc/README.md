# القاضي | دورة من الطلب إلى التحصيل

ملفات التنفيذ المترابطة داخل نسخة Archify الخاصة بشركة القاضي.

- **order-to-cash.html** — واجهة عربية مستقلة مع RTL: خريطة عامة، مسارات الأقسام، عقد قابلة للنقر، الاعتماديات، قائمة إعداد من 23 مهمة مع حفظ محلي/تصدير، وعشرة اختبارات قبول.
- **order-to-cash.workflow.json** — تعريف Archify Workflow v2 الأصلي، يعرض سلسلة المستندات وأقسام التسليم والبوابات. يجب توليد HTML الأصلي باستخدام الـ CLI الموجود في هذا المستودع.
- **model.json** — بيانات الخطوات والحقول والاختبارات والمسؤولين وحالات الربط المغذّية لواجهة التنفيذ.

## توليد المخطط الأصلي من نسخة Archify

من جذر المستودع:

```bash
node archify/bin/archify.mjs finalize workflow docs/alqadi-otc/order-to-cash.workflow.json docs/alqadi-otc/order-to-cash.archify.html --quality standard --json
```

أو عند عدم توافر بيئة Chromium اللازمة لفحص `finalize`، استخدم أوامر التحقق والتوليد من `archify/SKILL.md` دون اعتبار العملية ناجحة إلا عند ظهور إيصال التحقق.

## حدود الدقة

مخطط التشغيل والموافقة والانتقالات المقترحة **ليس** انعكاساً لإعدادات ERPNext الحية. مصدر حقول وسلوكيات أساسية مستمد من مكتبة Frappe Expert؛ يجب مراجعة الإصدار الفعلي وCustom Fields وWorkflows والصلاحيات والتجارب على موقع تجريبي قبل القبول. الربط بـCRM وHelpdesk وRaven مشروط، ولا يجوز عرضه كتكامل مفعل.

اختبار الواجهة العربية للملف `order-to-cash.html`: Chromium على 1440×900 و390×900؛ تحقّق من 13 عقدة و8 اعتماديات و23 مهمة و10 اختبارات وفتح بطاقة التفاصيل وإغلاقها واتجاه HTML وعدم وجود أخطاء JavaScript أو تجاوز أفقي عام. **لا يشمل هذا الاختبار المخطط الأصلي المولّد من Archify ولا ERPNext الحي.**
